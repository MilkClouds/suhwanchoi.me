# suhwanchoi.me

Personal website, blog, and CV repository. Originally based on [jonbarron.github.io](https://github.com/jonbarron/jonbarron.github.io).

## Structure

- `site/` — everything that builds the deployed website.
  - `site/public/` — homepage and static assets, deployed to [suhwanchoi.me](https://suhwanchoi.me) via GitHub Actions. The `site/public/blog/` subtree is built from `site/blog/` by Quarto and is **not tracked** in git (see `.gitignore`).
  - `site/blog/` — Quarto source for the blog. Posts live in `site/blog/posts/*.qmd`. Renders into `site/blog/_site/`; `site/scripts/build.sh` copies that output into `site/public/blog/`.
  - `site/cv/` — CV LaTeX source. `site/cv/suhwan_choi_cv.pdf` is **built by `site/scripts/build.sh`** (not tracked in git, see `.gitignore`) and reachable from the site at `/suhwan_choi_cv.pdf` via a symlink in `site/public/` (replaced by the real PDF when the site is assembled into `_site/`).
  - `site/scripts/build.sh` — assembles the deployable site into `_site/`; run by both local preview and CI. `site/scripts/serve.sh` builds and serves it locally.
- `profile/` — how I present myself (not part of the deployed site).
  - `profile/pitch/` — Beamer research pitch deck ([git submodule](https://github.com/MilkClouds/pitch)).
  - `profile/milkclouds/` — [GitHub profile](https://github.com/MilkClouds/milkclouds) (git submodule).
- `misc/` — everything else.
  - `misc/posters/` — conference posters (store-only, not web-served).
  - `misc/star-manager/` — script to sync GitHub Star Lists (see its own README).

## How to build CV

`site/cv/suhwan_choi_cv.pdf` is built automatically by CI on every deploy (see [Deployment](#deployment)) — just edit `site/cv/suhwan_choi_cv.tex`, commit, and push. The PDF is **not tracked** in git.

To preview locally (optional):

- VSCode: install the LaTeX Workshop extension, open `site/cv/suhwan_choi_cv.tex`, press `Option+Command+B`. Output at `site/cv/suhwan_choi_cv.pdf`.
- CLI: `latexmk -pdf -interaction=nonstopmode site/cv/suhwan_choi_cv.tex`

## How to serve website locally

```bash
bash site/scripts/serve.sh        # → open http://localhost:8000/
bash site/scripts/serve.sh 4000   # custom port
```

This runs `site/scripts/build.sh` (the same script CI runs) to assemble `_site/` — CV PDF via `latexmk`, blog via `quarto`, CV symlink replaced by the real PDF — then serves `_site/`. Needs `latexmk` and `quarto` on `PATH`.

Don't serve `site/public/` directly — the CV at `/suhwan_choi_cv.pdf` is a symlink to `site/cv/suhwan_choi_cv.pdf` (gitignored, and a plain text stub on Windows checkouts), and `site/public/blog/` is generated by Quarto. Neither exists in a fresh checkout, so the CV and blog links break.

For live blog editing with auto-reload (blog content only; won't show the homepage):

```bash
quarto preview site/blog
```

## How to add a blog post

1. Create `site/blog/posts/<slug>.qmd` with front matter:
   ```yaml
   ---
   title: "Post title"
   description: "One-sentence summary used for previews + the listing page."
   date: 2026-04-27
   categories: [tag1, tag2]
   ---
   ```
2. Write Markdown. Cite from a bibliography declared in the post front matter, usually a per-post `.bib` next to the `.qmd`, with `[@key]`. Math, footnotes, cross-refs all supported by Pandoc.
3. `quarto render site/blog` to preview locally.
4. Commit `site/blog/` (output is gitignored) and push to `main` — CI rebuilds and redeploys.

## Deployment

`.github/workflows/pages.yml` has two jobs:

- **build** (every push and pull request): installs TeX Live + Quarto, then runs `site/scripts/build.sh` — the same script used for local preview — which builds the CV PDF, renders the blog, and assembles `_site/` (CV symlink replaced by the real PDF). `actions/upload-pages-artifact@v4` uploads `_site/`. PRs run this, so build breakage is caught before merge.
- **deploy** (pushes to `main` only): `actions/deploy-pages@v5` publishes the artifact.

Because local preview and CI both run `site/scripts/build.sh`, what you see locally is what CI deploys.
